# Until Dawn Native PC Recompilation – v0.2.1

**Tag:** `v0.2.1` · **Asset:** `UntilDawn_0.2.1.zip`

> [!WARNING]
> This is still an **early work-in-progress test release**. Expect bugs, crashes, graphical problems and pauses.
> v0.2.1 prepares the game's shaders before it starts, so the scenes it covers no longer pause to compile them
> during play, but the **memory corruption behind most crashes is not fixed yet**, the heaviest scenes still run
> below 30 FPS, and a number of graphical glitches remain (see Known issues).

> [!IMPORTANT]
> **No game files are included.** You need a decrypted dump of the original PS4 Until Dawn (**CUSA02636**) with
> the **01.03** update, made from your own **legally obtained** copy of the game. This download does not contain
> the game.

## What's new in 0.2.1

All fixes from 0.2.0 and earlier are kept. Figures are from the development PC (RTX 3090 Ti, Core i9-12900KF, 64 GB).

### Shader preparation

- **Shaders are compiled before the game starts.** Before the brightness screen, a "Preparing shaders" screen (in
  the game's own typeface) compiles the shaders the game will need, so they are not compiled in the middle of play.
  Esc or Circle skips it; anything skipped is compiled during play, as before. Nothing is shown when everything is
  already prepared.
- **The first start uses a shader list that comes with the program** (`pipelines.udm`, next to `UntilDawn.exe`): 1,594
  shader combinations recorded from 17 scenes, a play session and translation traces. The list holds no game code: it
  says where each shader is in your own game files and how it was set up, and the program reads the shaders from
  your files, translates them and checks each result against the recorded one before compiling it.
- **Later starts** also prepare everything earlier sessions needed. Shaders already in the cache are only checked
  (under a second for all of them); after a graphics driver update they are compiled again automatically.
- **Measured:** a first start compiled the list in 30–40 seconds; the first-start sequence played after it
  (brightness, controls, intro movie, main menu) compiled no shaders at all (219 combinations, all prepared). In
  replays of scenes that were left out of the list on purpose, 85–88%
  of their shaders were ready and the renderer waited about 2.7 seconds instead of 19–28 seconds.
- New setting `shader_preparation` (`1` by default, `0` turns it off).

### Fixed

- A rare **hang of the renderer while new textures were converted** on its helper threads: a helper still finishing
  one job could take a piece of the next one and drop it, and the renderer then waited for that piece forever.
  Found in a test replay (the replay watchdog ended it after 120 seconds) and reproduced off-line; the same hang was
  possible in play.

### Changed

- Fewer copies of the same shader: inputs a shader stage never reads no longer split it into separate translations,
  and translations with identical results share one compiled pipeline.
- Less renderer CPU time for checking shaders and binding unchanged textures.
- Geometry-shader passes compile in about a third of the time and take about half the GPU time.

## Known issues

- **Not every scene is in the shader list yet.** Scenes nobody has recorded (for example the main-menu background of
  later chapters) still pause to compile their shaders the first time; they are prepared from the next start on.
- **A second form of a few shaders:** some shaders read data the graphics card writes itself every frame and can come
  out in either of two (correct) forms depending on timing; the second form is compiled once when it first appears.
- The **black screen of about a second before the main menu** is the game loading the scene and its textures (no
  shader compilation in the logs); it remains.
- The **memory corruption** behind most crashes is not fixed yet; **frame rate** below 30 FPS in the heaviest scenes.
- **New in this version:** shader preparation has only been tested on the development PC (NVIDIA). Reports from
  **AMD and Intel** GPUs are especially welcome. If 0.2.1 crashes or stutters where 0.2.0 did not, please report it
  (and try `shader_preparation = 0`).

Full list: [Known issues](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/KNOWN_ISSUES.md)

## Updating from 0.2.0

Copy the new `UntilDawn.exe`, the new `pipelines.udm`, `compat\ud_compat.exe` and the text files into your 0.2.0
folder. **Do not overwrite** `Config\settings.ini`, `savedata\` or `Game\` (your settings, saves and game). Saves,
settings and `Cache\` carry over; the new setting `shader_preparation` uses its default (on) when it is not in your
`settings.ini`. The first start shows the "Preparing shaders" screen.

**Download check:** `UntilDawn_0.2.1.zip` SHA-256
`818b1aab643b54a0c2f051943025d8b2ec1d1467882941490b9302d005b00779`

## Getting started

1. Download **`UntilDawn_0.2.1.zip`** below and extract it to a folder you can write to.
2. Put your game files in the `Game` folder (so that `Game\eboot.bin` exists), or set `game_dir` in
   `Config\settings.ini`.
3. Start **`UntilDawn.exe`**. The first start prepares the shaders (about half a minute or more).

Full instructions: [Installation guide](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/INSTALLATION.md)
· [Controls](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/CONTROLS.md)

## Requirements

- Windows 10 or 11, 64-bit
- CPU with AVX, F16C, BMI1, LZCNT, POPCNT and MOVBE (Intel Haswell / AMD Ryzen or newer)
- 16 GB memory recommended; keep the Windows page file on
- GPU with a current Vulkan 1.3 driver (NVIDIA tested; AMD tested with 0.1.3; Intel untested)

## Help wanted: hardware testing

Reports from **AMD and Intel GPUs** and from **laptops with two GPUs** are especially welcome. Run
`compat\run_compat.bat` and attach the resulting `compat_report.zip` to a
[compatibility report](https://github.com/SuperCatElvis/UntilDawn_PC/issues/new/choose), with screenshots if
anything looks wrong, and say whether you changed `renderer_thread`, `present_mode` or `shader_preparation`.
