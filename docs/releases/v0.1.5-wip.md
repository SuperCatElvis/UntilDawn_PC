## What's new in 0.1.5

0.1.5 concentrates on memory use, shader-compilation freezes and the renderer's own work. All fixes from 0.1.3 and
0.1.4 are kept. The shader translator produces exactly the same GPU programs as in 0.1.4, and frames replayed with
every test build matched the build before it (within the small run-to-run differences the GPU itself shows), so
the picture is meant to be unchanged. Figures are from the
development PC (RTX 3090 Ti, Core i9-12900KF, 64 GB) on the same test route through the prologue.

### Memory

- **About a third less RAM:** at most about **8.2 GB** in RAM instead of 12.7 GB, and at most about **17 GB**
  committed instead of 22 GB. The game's memory no longer grows by hundreds of MB during play (+44 MB instead of
  +640 MB in ten minutes). What changed:
  - The game's many small memory heaps are committed in steps as the game uses them, instead of 64 MB or more each
    up front; memory pools grow in 64 MB steps instead of 512 MB.
  - Translated shader programs are freed once the graphics driver has its own copy; shader modules that are not
    being used are destroyed and rebuilt when needed from a compressed copy; the translator's cache is packed.
- **Video memory sized to your GPU:** the renderer's buffer copies and memory mirror now take at most a quarter
  and an eighth of the GPU's video memory, instead of a fixed 6 GB and 3 GB on every card.
- A **memory report** in the log every 60 seconds and at exit, useful for crash and memory reports.

### Shader compilation

- **Compute shaders are compiled in parallel**, like the other shaders, instead of one after another on the
  renderer thread. A 38-second freeze reported with 0.1.4 on a 6-thread CPU held 30 seconds of such compiles. With
  no shader cache, the time spent waiting for compiles in two test scenes on the development PC fell by 16% and
  24%. With compute shaders made to fail on purpose, the pictures were the same as with the old way.

### Renderer

- **Less redundant work:** pipeline, viewport, scissor, blend constants, shader constants and index buffer are only
  sent to the driver when they change between draws — about 3% less renderer time in test scenes.
- **Cheaper memory checks:** the per-submit check for memory the game has written saves most of its reset calls
  (0.3–0.4 ms less per frame in play). Verified to miss nothing in about 1.1 million skipped ranges.
- **Moved textures reused:** when the game moves a texture to a new place in memory, it takes over its existing
  copy in video memory instead of being uploaded again (about 1.3 GB less uploading on the test route). Reuse
  requires every byte and the layout to match.
- Textures lying across two neighbouring blocks of game memory are no longer refused.

The frame rate is similar to 0.1.4, slightly better in places: on the development PC light scenes often reach
60 FPS, busy scenes run at about 35–45 FPS and the heaviest scenes (the prologue's "stranger" shots) at about
22–27 FPS.

## Known issues

- **Crashes from overwritten game memory — not fixed.** Now and then the lowest byte of a pointer in the game's
  memory is set to zero (in the cases examined, at the start of a 4 KB page), and the game crashes later. Seen on
  the development PC and on players' PCs with 0.1.3 and 0.1.4, and twice (without a crash) in the final 0.1.5
  test; 0.1.5 does not change it. Saves are kept. Logs with `EBOOT POINTER LOW BYTE CLEARED` lines help the
  investigation.
- **Laptops with two GPUs** (NVIDIA plus integrated graphics driving the screen): very slow frame presentation,
  hangs ending in "device lost", and flickering UI in the Status / Collectibles menus have been reported
  ([#2](https://github.com/SuperCatElvis/UntilDawn_PC/issues/2)). Try Windows' Graphics settings → `UntilDawn.exe`
  → **High performance**, or the laptop's discrete-GPU (MUX) mode.
- Characters occasionally deform for a frame or two (most likely the same memory problem).
- Graphics: light squares on Emily's eyes and dark squares on a wall in the prologue; the arm and inspected item
  invisible during item inspection on one PC ([#3](https://github.com/SuperCatElvis/UntilDawn_PC/issues/3)); the
  Skip prompt's "Skip" text as white boxes on some movies; black mouths in some close-ups, a red flash in the
  Episodes menu, smeared end-credits text; fog that disappears for a frame in the second "stranger" shot.
- **Frame rate:** the heaviest scenes are still below 30 FPS. **Shader compilation** still causes freezes on the
  first play-through, of 10–20 seconds or more on CPUs with few cores.
- No vibration or light bar on PlayStation controllers yet.
- **New in this version:** 0.1.5's changes have only been played on the development PC (NVIDIA). Nothing in them
  is written for one GPU make, but they are untested on AMD and Intel: reports from **AMD and Intel** GPUs, and from PCs with 16 GB of RAM, are especially
  welcome. If 0.1.5 crashes or stutters where 0.1.4 did not, please report it.

Full list: [Known issues](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/KNOWN_ISSUES.md)

## Updating from 0.1.4

Copy the new `UntilDawn.exe` and the text files into your 0.1.4 folder. **Do not overwrite**
`Config\settings.ini`, `savedata\` or `Game\` (your settings, saves and game). Or extract 0.1.5 to a new folder and
copy your `settings.ini`, `savedata` and game files over. There are no new settings, `compat\` is unchanged, and the
shader cache (`Cache\`) from 0.1.4 stays valid. From 0.1.3 or 0.1.2, also copy `compat\ud_compat.exe`.

**Download check:** `UntilDawn_WIP_0.1.5.zip` SHA-256
`7af63a61e5b91492366482f3eb610df06867c64fed5ce69a958b5996777a9ea9`

## Getting started

1. Download **`UntilDawn_WIP_0.1.5.zip`** below and extract it to a folder you can write to.
2. Put your game files in the `Game` folder (so that `Game\eboot.bin` exists), or set `game_dir` in
   `Config\settings.ini`.
3. Start **`UntilDawn.exe`**.

Full instructions: [Installation guide](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/INSTALLATION.md)
· [Controls](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/CONTROLS.md)

## Requirements

- Windows 10 or 11, 64-bit
- CPU with AVX, F16C, BMI1, LZCNT, POPCNT and MOVBE (Intel Haswell / AMD Ryzen or newer)
- 16 GB memory recommended; keep the Windows page file on
- GPU with a current Vulkan 1.3 driver (NVIDIA tested; AMD tested with 0.1.3; Intel untested)

## Help wanted: hardware testing

Reports from **AMD and Intel GPUs** are especially welcome. Run `compat\run_compat.bat` and attach the resulting
`compat_report.zip` to a [compatibility report](https://github.com/SuperCatElvis/UntilDawn_PC/issues/new/choose),
with screenshots if anything looks wrong, and say whether you changed `renderer_thread`.
