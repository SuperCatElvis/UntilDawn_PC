# Until Dawn Native PC Recompilation – v0.3.0

**Tag:** `v0.3.0` · **Asset:** `UntilDawn_0.3.0.zip`

> [!WARNING]
> This is still an **early work-in-progress test release**. Expect bugs, crashes, graphical problems and pauses.
> v0.3.0 fixes two of the worst graphical faults of the later chapters (the lake water vanishing and characters'
> geometry stretching across the screen), a crash when loading chapters, and has a bigger shader list. The
> **memory corruption behind most crashes is not fixed yet**, the heaviest scenes still run below 30 FPS, and a
> number of graphical glitches remain (see Known issues).

> [!IMPORTANT]
> **No game files are included.** You need a decrypted dump of the original PS4 Until Dawn (**CUSA02636**) with
> the **01.03** update, made from your own **legally obtained** copy of the game. This download does not contain
> the game.

## What's new in 0.3.0

v0.3.0 replaces the planned 0.2.2 (never released) and contains everything prepared for it. All fixes from 0.2.1
and earlier are kept. Figures are from the development PC (RTX 3090 Ti, Core i9-12900KF, 64 GB).

### GPU coherence (new, on by default)

On the PS4, the CPU and the graphics card share one memory. On a PC they do not: the program keeps copies of
GPU-written data on the graphics card, and until now the CPU side could go on using the older bytes in system memory
after the graphics card had changed them, or send its older bytes back over newer GPU results. In the later chapters
this caused visible damage:

- **Characters' geometry stretched across the screen** (Chapter 10, the Josh section; huge triangles over Sam and the
  scene). The graphics card moved character model data, and the CPU then copied hair indices from the old location.
- **The lake water disappeared** (seen in Chapter 10). A few hundred bytes of old data were copied over the ocean
  simulation's state on the graphics card; the simulation then produced invalid values for the rest of the session.

The new **GPU coherence** layer keeps both sides consistent: memory the graphics card has written is guarded, and a
CPU access to it first fetches the graphics card's current bytes; CPU writes reach the graphics card in the right
order. Both problems are gone in the recorded scenes and in the automated tests built from them, and the scene
change where the lake data is damaged (in Chapter 8) is handled correctly in automated runs; neither has yet been
checked in a full play-through.

- **Cost:** about 30–50 microseconds of CPU time per frame on the development PC; frame rates, frame-time
  percentiles and loading times are the same with and without it within measurement noise (11 chapter starts, 46
  recorded scenes and a replay benchmark, each with and without it).
- **Turning it off for troubleshooting:** `gpu_coherence = 0` in `Config\settings.ini` (or `--no-gpu-coherence`).
  The first lines of `Logs\UntilDawn.log` say whether it is on.
- **If it cannot work safely** (for example if other software interferes with it), the game stops with a message
  that says so and how to turn it off, rather than going on with memory that may be wrong. If it cannot be set up at
  all, the log says so and the game runs without it.

### Stability

- **Fixed: crash when loading a chapter** (`FIXED mapping moved` in the log, on the "Lump Loader" thread, for example
  when loading Chapter 8). Freeing part of the address range kept for the game let Windows put its own memory there,
  and the game's next fixed-address mapping then failed. The rest of the range now stays reserved.
- **Fixed: two threads could both construct the same shared object.** The program's version of the C++ "construct this
  once" routine did not make a second thread wait while the first was still constructing; in automated chapter runs
  this happened in about one run in four. It now waits, as on the PS4. This is one possible source of the memory
  corruption described below, not its main cause: in 22 runs with the fix against 22 without, the detected damage was
  lower (13 against 21), but within chance.

### Graphics

- **Fixed:** the letterbox bars of the character introductions (Mike, Jess, Chris, Josh, …) stopped short of the right
  and bottom edges, leaving a strip of the scene visible. Checked against PS4 screenshots of the same cards.
- **Fixed:** some small textures that the game rewrites in place were not noticed as changed (the quick check samples
  only part of a texture) and kept showing old contents. Textures up to 1 MB are now compared in full when the quick
  check says "unchanged".

### Shader preparation

- **The shader list now covers the opening of every chapter:** `pipelines.udm` now holds 4,440 shader combinations
  (0.2.1: 1,594). The new ones were recorded in play sessions from the prologue to the middle of Chapter 1, from
  the start of every chapter (0 to 10, loaded from the Episodes menu) and from parts of Chapter 10. As before, the list holds no
  game code: it says where each shader is in your own game files, and the program translates it again from them and
  checks the result before compiling it. All 4,440 were translated exactly as recorded and compiled without a failure.
- **Measured (automated starts of chapters 0–10, the same route with each list, development PC):** 98.9% of the shader
  combinations the sessions used were ready before the game started, against 78.7% with the 2,525-combination list
  prepared for 0.2.2; shader
  compiling during play fell from about 135 seconds in all to about 3.5 seconds, and the longest single frame of a
  chapter start (loading included) from up to 3.3 seconds to at most 1.2 seconds. The sessions recorded for the list came from the
  same kind of chapter starts, so scenes further into each chapter can still compile shaders the first time.
- **The first start takes longer:** preparing the list took about 2½ minutes on the development PC with nothing
  cached at all (the 2,525-combination list: just under 2 minutes in the same test). Later starts take about half a second. Esc or
  Circle still skips it; whatever is skipped is compiled during play.
- **Optional background preparation (test option):** `shader_preparation = 2` shows the preparation screen for at most
  20 seconds and compiles the rest during play on low-priority threads. Off by default; measured about 8% slower
  frames while it runs.

### Improvements

- **Optional extra: Halloween Hunt 2015 restored (off by default).** In 2015 the PS4 game ran a short Halloween
  event: from 28 to 31 October it showed a Halloween screen when the game started and hid pumpkins in the game world.
  The event is still in the game's own files and code, but it only switches on when the date falls in those days of
  2015. With **`halloween_hunt = 1`** in `Config\settings.ini` (or the `--halloween-hunt` start option), the program
  answers only the game's Halloween date checks with 31 October 2015 - the original screen and pumpkins appear, by the
  game's own logic. Your Windows date is not changed and nothing else in the game sees another date; turn it on or off
  whenever you like (restart the game after changing it). The first lines of `Logs\UntilDawn.log` say whether it is on.
  - A thin yellow outline along the left edge of the Halloween screen, which the PS4 does not show, is left out while
    the option is on.
  - Tested briefly: the Halloween screen and a pumpkin in the mines; with the option off the game starts as usual.
    Not every pumpkin has been looked for.

## Known issues

- The **memory corruption** behind most crashes is not fixed yet (see Known issues for what is known now). In
  automated chapter runs the safeguards detect damage somewhat less than once per 2½-minute run on average; most of
  it does not lead to a crash, but crashes from it remain possible. Saves are kept; start the game again.
- **Frame rate** is below 30 FPS in the heaviest scenes.
- **Not every scene is in the shader list yet:** scenes further into a chapter than its opening can still pause to
  compile shaders the first time; they are prepared from the next start on.
- **Chapter 10:** a black screen in one scene (seen once, after the long route through the chapter), red/blue frames
  in the Matt and Jess scene (not seen again since the texture fix) and exploded character geometry in other sections
  have not been re-checked in play since GPU coherence; please report them if they still happen.
- **GPU coherence** has so far been tested on the development PC only (NVIDIA). Reports from AMD and Intel GPUs are
  especially welcome; if anything looks broken only with it on, try `gpu_coherence = 0` and report both results.

Full list: [Known issues](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/KNOWN_ISSUES.md)

## Updating from 0.2.1

Copy the new `UntilDawn.exe`, the new `pipelines.udm`, `compat\ud_compat.exe` and the text files into your 0.2.1
folder. **Do not overwrite** `Config\settings.ini`, `savedata\` or `Game\` (your settings, saves and game). Saves,
settings and `Cache\` carry over; the first start shows the "Preparing shaders" screen for the new shaders in the
list. GPU coherence is on without any change to `settings.ini`. From 0.2.0 or earlier, see the
[installation guide](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/INSTALLATION.md#updating-from-an-earlier-release).

**Download check:** the SHA-256 of `UntilDawn_0.3.0.zip` is given on the release page and in `UntilDawn_0.3.0.zip.sha256.txt`.

## Getting started

1. Download **`UntilDawn_0.3.0.zip`** below and extract it to a folder you can write to.
2. Put your game files in the `Game` folder (so that `Game\eboot.bin` exists), or set `game_dir` in
   `Config\settings.ini`.
3. Start **`UntilDawn.exe`**. The first start prepares the shaders (about 2½ minutes on the development PC, longer
   with fewer CPU cores).

Full instructions: [Installation guide](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/INSTALLATION.md)
· [Controls](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/CONTROLS.md)

## Requirements

- Windows 10 or 11, 64-bit
- CPU with AVX, F16C, BMI1, LZCNT, POPCNT and MOVBE (Intel Haswell / AMD Ryzen or newer)
- 16 GB memory recommended; keep the Windows page file on
- GPU with a current Vulkan 1.3 driver (NVIDIA tested; AMD tested with 0.1.3; Intel untested)

## Help wanted: hardware testing

Reports from **AMD and Intel GPUs** and from **laptops with two GPUs** are especially welcome. Run
