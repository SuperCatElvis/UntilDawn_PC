# Until Dawn Native PC Recompilation – WIP 0.2.0

**Tag:** `v0.2.0-wip` · **Asset:** `UntilDawn_WIP_0.2.0.zip`

> [!WARNING]
> This is still an **early work-in-progress test release**. Expect bugs, crashes, graphical problems and pauses.
> WIP 0.2.0 fixes several long-standing stability and graphical problems, but the **memory corruption behind
> most crashes is not fixed yet**, the heaviest scenes still run below 30 FPS, and a number of graphical glitches
> remain (see Known issues).

> [!IMPORTANT]
> **No game files are included.** You need a decrypted dump of the original PS4 Until Dawn (**CUSA02636**) with
> the **01.03** update, made from your own **legally obtained** copy of the game. This download does not contain
> the game.

## What's new in 0.2.0

0.2.0 is mostly about fixing things that were wrong for a long time, each traced to its cause with logs, frame
captures and offline reproductions rather than worked around. All fixes from 0.1.3 to 0.1.5 are kept. Figures are
from the development PC (RTX 3090 Ti, Core i9-12900KF, 64 GB). Items under "Changed" still need confirming in play.

### Fixed

- **Collectibles and item inspection** ([#3](https://github.com/SuperCatElvis/UntilDawn_PC/issues/3)): the
  character's arm and hand, and the clue or totem in it, no longer disappear when an item is picked up or
  inspected. Two tables of floating-point limits that the game reads from the PS4's C library (`_Flt` and `_Dbl`:
  the smallest, largest and "epsilon" values) were handed to the game as zeros. With a smallest value of 0, a check
  in the arm's two-bone IK no longer caught a zero-length direction, divided by zero and filled the arm's bones with
  invalid numbers. Found by replaying the exact recorded IK call outside the game: with the zero tables it produces
  the invalid result, with the correct values a valid one. Every other place in the game's code that reads these
  tables (142 reads of `_Flt` and 3 of `_Dbl` in the main executable) now gets the right values too. Confirmed in
  play.
- **Mike's lantern arm** in Chapter 5 no longer comes apart from him — the same cause, fixed by the same change.
  Confirmed in play.
- **Black mouths** in close-ups in Chapter 2 and later, after playing the prologue: identical copies of a character
  shader at different addresses shared one translation that still read the first copy's constant table, in memory
  the game had since reused. Confirmed in play.
- **X (Cross) button prompts** are no longer striped or garbled (a texture layout rule sheared some UI textures),
  and the **white flash on the character introduction name cards** is gone. Confirmed in play.
- **Freezes of a second or more:** writing a line to the log could block the game or the renderer when Windows
  held the write (1.2 s in one measured frame). Log lines are now written by a separate thread; no such freeze has
  been seen in the test sessions since.
- **A random crash at start-up** (`FIXED mapping moved` in the log): Windows sometimes placed a thread's stack in
  the address range the game uses for its heaps. That range is now kept free from the start.

### Changed — should fix, not yet confirmed in play

- **Long sessions:** after about 25–30 minutes of play, the game's heaps had moved past the range of memory the GPU
  can see, so data loaded after that time read as zeros (most likely behind every character "exploding" at once,
  and missing or broken graphics, late in long sessions). The heaps now stay inside that range, and a released heap
  is reused at once, which keeps the memory committed for the heaps at the level of the heaps in use. Found from the
  logs; 0.2.0 has not yet been played for longer than about ten minutes at a time.
- **The aiming reticle** (gun tutorial) should no longer show as a flickering red square: a UI target was drawn
  into an older, shorter image at the same address, and the reticle then read a still older, larger one. Checked
  on the frame capture of the problem.
- **Music after a skipped movie:** a skip now also stops the music and other sounds posted since the movie started
  (meant for the song that kept playing after skipping the Chapter 1 bus ride).
- **Laptops with two GPUs** ([#2](https://github.com/SuperCatElvis/UntilDawn_PC/issues/2)): when the display did
  not hand back an image in time, the program carried on as if it had one, and the GPU then waited for ever ("device
  lost"). Now that frame is skipped, and with `present_mode = auto` repeated slow presents switch to the `fifo`
  presentation mode by itself. New settings `present_mode` and `gpu`. **Not yet tested on such a laptop** (on the
  development PC a frame never arrived late, so the skip itself has not run yet) — reports are very welcome.

### Also

- **Less work per new texture:** large textures are de-tiled on helper threads, and new textures take their video
  memory from shared blocks instead of an allocation each.
- **The memory corruption** (still open) was narrowed down: hardware watchpoints caught the writer — the game's own
  code finishing an object whose memory overlaps another object still in use. One race in the game's arena
  allocator was found and is now prevented by a lock; the damage still occurs, so the search goes on.

### Notes

- **Shader-compilation pauses are not improved yet:** with an empty shader cache (a new install) the development
  PC paused once for about 12 seconds and a few times for 3–8 seconds in the first minutes, mostly while large
  compute shaders were compiled; once the cache holds an area, new content costs up to about 2 seconds. CPUs with
  fewer cores pause longer. Every shader is translated anew (the GPU's memory window and the character shaders
  changed), so after updating these pauses return once; the contents of the old `Cache\` folder no longer match
  (you can delete it).
- `compat\ud_compat.exe` is rebuilt with 0.2.0's shader translator.
- **Frame rate and memory use were not a focus of this release** and are about the same as 0.1.5 on the same
  prologue route (clean-install tests): similar frame rate (the
  heaviest "stranger" shot at about 22–25 FPS in both, busy scenes about 30–40 FPS); at most about 8.8 GB in RAM and
  18 GB committed (0.1.5: 8.2 GB and 17 GB).

## Known issues

- **Crashes from overwritten game memory — not fixed.** Now and then the lowest byte of a pointer in the game's
  memory is set to zero, and the game crashes later. Seen with every version so far, including in testing of 0.2.0
  (detected, no crash). Saves are kept. Logs with `EBOOT POINTER LOW BYTE CLEARED` lines help the investigation.
- **Laptops with two GPUs:** see above; the slow presenting itself and flickering menus may remain. Try Windows'
  Graphics settings → `UntilDawn.exe` → **High performance**, or the laptop's discrete-GPU (MUX) mode.
- **Graphics:** flickering spots on the R2 choice cards and flickering subtitles; a see-through strip in the black
  bar of the character introductions for a few frames; a slight lighting effect on Chris's glasses (not yet
  checked); the main-menu character animating too fast; light squares on Emily's eyes and dark squares on a wall in
  the prologue; totem visions that lose their background or UI; the Skip prompt's "Skip" text as white boxes on
  some movies; a red flash in the Episodes menu; smeared end-credits text; fog that disappears for a frame in the
  second "stranger" shot.
- Characters occasionally deform for a frame or two (most likely the same memory problem).
- **Shader-compilation pauses** on the first play-through (up to about 12 seconds on a new install even on the
  development PC, longer on CPUs with few cores); **frame rate** below 30 FPS in the heaviest scenes.
- No vibration or light bar on PlayStation controllers yet; keys cannot be remapped yet.
- **New in this version:** 0.2.0's changes have only been played on the development PC (NVIDIA). Reports from
  **AMD and Intel** GPUs, from laptops with two GPUs and from long sessions are especially welcome. If 0.2.0
  crashes or stutters where 0.1.5 did not, please report it.

Full list: [Known issues](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/KNOWN_ISSUES.md)

## Updating from 0.1.5

Copy the new `UntilDawn.exe`, `compat\ud_compat.exe` and the text files into your 0.1.5 folder. **Do not
overwrite** `Config\settings.ini`, `savedata\` or `Game\` (your settings, saves and game). Or extract 0.2.0 to a
new folder and copy your `settings.ini`, `savedata` and game files over. The new settings (`gpu`, `present_mode`,
`heap_slot_mb`, `heap_slot_reuse`) use their defaults when they are not in your `settings.ini`.

**Download check:** `UntilDawn_WIP_0.2.0.zip` SHA-256
`ed9098a8f215607e88d541b2ab7401637bf1e5ba3b88dada939492e152933217`

## Getting started

1. Download **`UntilDawn_WIP_0.2.0.zip`** below and extract it to a folder you can write to.
2. Put your game files in the `Game` folder (so that `Game\eboot.bin` exists), or set `game_dir` in
   `Config\settings.ini`.
3. Start **`UntilDawn.exe`**.

Full instructions: [Installation guide](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/INSTALLATION.md)
· [Controls](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/CONTROLS.md)

## Requirements

- Windows 10 or 11, 64-bit
- CPU with AVX, F16C, BMI1, LZCNT, POPCNT and MOVBE (Intel Haswell / AMD Ryzen or newer)
- 16 GB memory recommended; keep the Windows page file on
- GPU with a current Vulkan 1.3 driver (NVIDIA tested; AMD tested with 0.1.3; Intel untested)
