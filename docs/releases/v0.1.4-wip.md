# Until Dawn Native PC Recompilation – WIP 0.1.4

**Tag:** `v0.1.4-wip` · **Asset:** `UntilDawn_WIP_0.1.4.zip`

> [!WARNING]
> This is still an **early work-in-progress test release**. Expect bugs, crashes, graphical problems and stutters.
> The frame rate is much better than in 0.1.3, but the heaviest scenes still run below 30 FPS.

> [!IMPORTANT]
> **No game files are included.** You need a decrypted dump of the original PS4 Until Dawn (**CUSA02636**) with
> the **01.03** update, made from your own **legally obtained** copy of the game. This download does not contain
> the game.

## What's new in 0.1.4

All fixes from 0.1.3 are kept: long folder paths and the AMD graphics fixes. The shader translator still produces
exactly the same GPU programs as in 0.1.3.

### Fixes

- **See-through hair.** Fog and light-shaft effects behind characters were drawn over their hair, so hair looked
  hazy or see-through, for example Hannah's in the prologue. On the PS4 a compute shader writes the hair's depth
  into the depth buffer; that depth now reaches the renderer's depth buffer too. Confirmed in play.
- **More movies can be skipped:** the butterfly-effect tutorial, the movie that opens the prologue and the Chapter 1
  bus ride. As before, press any button, then Cross (Enter / Space). These movies now show the same Skip prompt as
  the intro logos and the end credits (its "Skip" text still shows as boxes on these movies; see Known issues).
- **Stability:** two changes aimed at the occasional crashes caused by overwritten game memory. New game memory is
  now registered with the graphics driver before the game gets to use it, and game file reads go through the
  program's own buffers. Both still need confirming with more play time. The memory safeguard also logs one more
  kind of damage, seen in a 0.1.3 crash report.

### Improvements

- **Performance.** On the development PC (RTX 3090 Ti, Core i9-12900KF), the heaviest scenes measured, the two
  "stranger" shots in the prologue, went from about 5 FPS in 0.1.3 to 21–25 FPS. Busy scenes (2,000–3,000 draws)
  now run at about 35–45 FPS, and light scenes reach 60 FPS more often. What changed:
  - Shader translation is about 3 times faster, and earlier translations are reused about 97% of the time instead
    of 29%. Most frames no longer translate anything.
  - The renderer runs on its own thread, alongside the game, instead of inside the game's frame. The new setting
    `renderer_thread = 0` in `Config\settings.ini` switches back to the 0.1.3 behaviour.
  - Fewer GPU synchronisation steps, more frames in flight, cheaper texture checks and uploads, textures written by
    the GPU no longer stall the renderer, faster memory copies.
- The renderer changes were reviewed for GPUs other than the development NVIDIA card. Two rare cases are fixed: an
  image could be freed while the GPU still used it after a batch was split in the middle of a draw, and two
  buffers now fall back to other memory when the preferred kind is not available (PCs without resizable BAR).
- The compatibility tester (`compat\run_compat.bat`) uses the new shader translator.

## Known issues

- **Frame rate:** the heaviest scenes are still below 30 FPS (21–25 FPS on the development PC). The first
  play-through still has shader-compilation pauses of 10–20 seconds.
- In the second "stranger" shot of the prologue, fog and haze can disappear for a frame or two just after the
  stranger walks past.
- Occasional crashes are still possible (saves are kept). Characters occasionally deform for a frame or two.
- The "Skip" text of the Skip prompt shows as white boxes on the butterfly-effect tutorial and the movie that
  opens the prologue, and can do so in the later "Previously on" clips (the Cross button is right, skipping works).
  The game's own text in that overlay movie is affected too, so it is a renderer fault; it is being investigated.
- Black mouths in some close-ups, a red flash in the Episodes menu, smeared end-credits text.
- No vibration or light bar on PlayStation controllers yet.
- **New in this version:** the performance changes have only been played on the development PC (NVIDIA). They are
  not specific to one GPU make, and the shader programs are unchanged from 0.1.3, but reports from **AMD and Intel**
  GPUs are especially welcome. If 0.1.4 crashes or stutters on your PC where 0.1.3 did not, set
  `renderer_thread = 0` in `Config\settings.ini` and tell us whether that helps.

Full list: [Known issues](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/KNOWN_ISSUES.md)

## Updating from 0.1.3

Copy the new `UntilDawn.exe`, `compat\ud_compat.exe` and the text files into your 0.1.3 folder. **Do not
overwrite** `Config\settings.ini`, `savedata\` or `Game\` (your settings, saves and game). Or extract 0.1.4 to a
new folder and copy your `settings.ini`, `savedata` and game files over. Your saves and settings work as they
are; `renderer_thread` does not need to be added (it defaults to 1). The shader cache (`Cache\`) from 0.1.3
stays valid, because the translated shaders are the same.

## Getting started

1. Download **`UntilDawn_WIP_0.1.4.zip`** below and extract it to a folder you can write to.
2. Put your game files in the `Game` folder (so that `Game\eboot.bin` exists), or set `game_dir` in
   `Config\settings.ini`.
3. Start **`UntilDawn.exe`**.

Full instructions: [Installation guide](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/INSTALLATION.md)
· [Controls](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/docs/CONTROLS.md)

## Requirements

- Windows 10 or 11, 64-bit
- CPU with AVX, F16C, BMI1, LZCNT, POPCNT and MOVBE (Intel Haswell / AMD Ryzen or newer)
- 16 GB memory recommended
- GPU with a current Vulkan 1.3 driver (NVIDIA and AMD tested with 0.1.3; Intel untested)

## Help wanted: hardware testing

Reports from **AMD and Intel GPUs** are especially welcome. Run `compat\run_compat.bat` and attach the resulting
`compat_report.zip` to a [compatibility report](https://github.com/SuperCatElvis/UntilDawn_PC/issues/new/choose),
with screenshots if anything looks wrong, and say whether you changed `renderer_thread`.
