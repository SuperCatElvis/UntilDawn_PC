Until Dawn native PC port - known issues (WIP 0.2.0, 29 October 2026)
=====================================================================

This is still a work-in-progress test build. What is known so far:

Not fixed yet: game memory that is occasionally overwritten (the main cause of crashes)
----------------------------------------------------------------------------------------
  - Now and then a single byte of the game's memory is set to zero - in the cases examined, the lowest byte of
    a pointer (often an object's type pointer). The game then follows a wrong pointer and crashes, for example
    in the "Lump Loader" or a "JobSched" thread, or a character's animation data is damaged. It has been seen on
    the developer's PC and on players' PCs with every version so far, and again while testing 0.2.0 (detected
    by the safeguards, no crash). 0.2.0 does NOT fix it. Saves are kept; start the game again.
  - What is known now: the byte is written by the game's own code, finishing a freshly made object whose memory
    overlaps another object that is still in use - two of the game's memory allocations overlap. One such race
    in the game's allocator was found and is now prevented by a lock, but the damage still occurs, so there are
    others. The investigation continues.
  - The program contains safeguards that detect the known kinds of damage and repair some of them. The log then
    contains lines such as "EBOOT POINTER LOW BYTE CLEARED" - please include the log (Logs\UntilDawn.log, or
    UntilDawn.previous.log after a restart) when you report a crash.
  - Characters can briefly deform ("explode") for a frame or two - most likely the same problem. (The case where
    every character exploded at once late in a long session most likely had another cause, changed in 0.2.0.)

Laptops with two graphics chips
-------------------------------
  - With 0.1.4, on a laptop with an NVIDIA GPU and AMD integrated graphics (RTX 5050 Laptop GPU + Radeon 740M)
    where the integrated chip drives the screen, showing a frame sometimes took 0.5-1 second, several runs hung
    for about 8-10 seconds and ended with "device lost", and the Status, Collectibles and character status menus
    flickered (GitHub issue #2).
  - 0.2.0 contains a fix for the part of this that was the program's fault: when a frame could not be handed
    to the screen in time, the program carried on as if it had been, and the graphics queue then waited for
    ever. Now that frame is skipped, and if presenting stays slow, the program switches to a safer presentation
    mode by itself (present_mode = auto). This has NOT been tested on such a laptop yet (on the developer's PC
    a frame never arrived late, so the skip itself has not run yet); the slow presenting itself and the
    flickering menus may remain.
  - Things to try:
      * Windows Settings > System > Display > Graphics: add UntilDawn.exe and choose "High performance".
      * If the laptop has a MUX switch / "discrete GPU only" mode, switch it on, so the NVIDIA GPU drives the
        screen directly.
      * present_mode = fifo in Config\settings.ini; gpu = 5050 (or another part of your GPU's name) picks a GPU.
    Please report what happened, with Logs\UntilDawn.log.

Stability
---------
  - Occasional crashes: see the first section. In a full play-through on the developer's PC (0.1.3) the game
    crashed twice and had to be restarted; players have reported similar crashes with 0.1.4.
  - The changes in 0.2.0 have only been played on the developer's PC (NVIDIA RTX 3090 Ti, Intel Core
    i9-12900KF). If 0.2.0 crashes, freezes or stutters on your PC where 0.1.5 did not, please report it.
    renderer_thread = 0 in Config\settings.ini (the renderer on the game's thread) is still available for
    freezes and stutters; it does not prevent the crashes from overwritten game memory.
  - Long sessions: 0.2.0 contains a fix for a problem that started after about 25-30 minutes of play (see
    CHANGELOG.txt), but 0.2.0 has not yet been played for longer than about ten minutes at a time. Reports from
    long sessions are very welcome - please say how long you had been playing.

Graphics
--------
  - The R2 choice cards can show flickering spots, and subtitles (for example in Chapter 1) can flicker.
  - The black bar at the bottom of the character introductions can show a see-through strip for a few frames.
  - A slight lighting effect on Chris's glasses (seen once with 0.2.0; possibly there before - not yet checked).
  - The character on the main menu animates much faster than it should (gameplay runs at the right speed).
  - Emily's eyes can show light squares for a couple of seconds, and the wall on the right as the friends leave
    the kitchen for the prank in the prologue can show dark square shadows (reported with 0.1.4 / 0.1.5; not
    re-checked with 0.2.0).
  - A red flash over the screen while moving through the Episodes menu.
  - The text at the start of the end credits is smeared vertically.
  - Totem visions: the video can play without the rest of the totem screen (its background and UI), e.g. when a
    totem is rewatched after it played correctly the first time; sometimes the whole UI disappears and only
    the character and the background remain.
  - In the second "stranger" shot of the prologue, fog and haze can disappear for a frame or two just after the
    stranger walks past. Rarely, lighting looks wrong for a frame or two elsewhere.
  - The Skip prompt's "Skip" text shows as white boxes on the butterfly-effect tutorial and the movie that opens
    the prologue, and can in the later "Previously on Until Dawn" clips (the Cross button is right and skipping
    works).
  - Prologue: icicles on the lodge can look solid black in the stranger cutscene; the falling snow can stop if
    the player stands still for a long time.
  - Small differences from the PS4 picture are possible elsewhere; please report anything that looks wrong.

Collectibles and animation
--------------------------
  - Fixed in 0.2.0: the arm, hand and picked-up item vanishing during pick-up and inspection, and (same cause)
    Mike's arm holding the lantern coming apart from him in Chapter 5 - both confirmed in play.
  - A clue has been seen to reappear after it was picked up (not re-checked with 0.2.0).

Audio and gameplay
------------------
  - Prologue: some audio is out of sync or late during the Dr Hill session and the Hannah and Beth chase.
  - Dr Hill, session 2: the fear book can show the same fear pictures again instead of the expected ones.
  - Music that kept playing after a skipped movie (for example the Chapter 1 bus ride): 0.2.0 stops the sounds
    posted since the movie started, but this has not been confirmed in play yet. If music keeps playing after a
    skip, please report which movie it was.

Performance
-----------
  - Shader compilation on the first play-through: the graphics driver compiles each new shader combination the
    first time it is needed. With an empty shader cache (a new install) the developer's PC paused once for
    about 12 seconds and a few times for 3-8 seconds in the first minutes of the prologue, mostly while large
    compute shaders were compiled; once the cache holds an area, new content costs up to about 2 seconds. CPUs
    with fewer cores pause longer (10-20 seconds or more have been reported with earlier versions). 0.2.0 does
    not improve this yet. The game is not hung - wait for it. Each pause happens once: the shader cache
    (Cache\) removes it on later runs. After updating from 0.1.5 the pauses return once, because every shader is
    translated anew.
  - The frame rate still varies by scene. On the developer's PC light scenes often reach 60 fps, busy scenes run
    at about 30-45 fps, and the heaviest scenes measured (the prologue's "stranger" shots) at about 22-29 fps -
    similar to 0.1.5 on the same route. Slower PCs will see lower numbers. The 60 fps limit is a limit, not a
    guaranteed frame rate. In the heaviest scenes the renderer's own work on the CPU is the limit; spreading it
    over several CPU cores is planned.
  - Long frames when the game loads a new scene are normal for now.

Memory
------
  - On the developer's PC the program used at most about 8.8 GB of RAM and committed up to about 18 GB on the
    prologue route (0.1.5: 8.2 GB and 17 GB), and 9.2 GB / 20 GB in a ten-minute session elsewhere in the game.
    Much of the committed memory is reserved by the graphics driver and not in RAM, but Windows needs room for
    it: keep the page file switched on ("System managed"). 16 GB of RAM is recommended (the program warns below
    12 GB).

Controllers and input
---------------------
  - Vibration and the light bar of DualSense / DualShock 4 controllers are not supported yet (Xbox controllers
    vibrate).
  - "Don't move" moments with a DualSense / DualShock 4: the motion indicator can drift to the left.
  - Keys cannot be remapped yet; L3 / R3 are not available on the keyboard.

Hardware
--------
  - Full play-through (0.1.3): Intel Core i9-12900KF + NVIDIA GeForce RTX 3090 Ti (drivers 617.42 and 621.01),
    Windows 11, 64 GB. 0.1.4, 0.1.5 and 0.2.0 have been played on the same PC.
  - Played by players with 0.1.4: Intel Core i5-9400F + GTX 1660 Ti (occasional crashes, see above), AMD Ryzen 5
    220 + RTX 5050 Laptop GPU / Radeon 740M (see "Laptops with two graphics chips").
  - Compatibility test passed (0.1.2 / 0.1.3): NVIDIA RTX 3060 Ti, 3080, 3090, 5070 and 5070 Laptop GPU,
    AMD Radeon RX 9070 XT, with Intel and AMD Ryzen CPUs.
  - AMD Radeon: 0.1.2 rendered badly on an RX 9070 XT; fixed in 0.1.3 and confirmed on that card. 0.1.4, 0.1.5
    and 0.2.0 have not been played on an AMD card yet - reports are welcome.
  - Intel Arc / integrated graphics are untested. Please run compat\run_compat.bat on these and send the report
    even if the game runs fine.
  - Game files reported "missing" although they are there: fixed since 0.1.3 for long folder paths. If one file
    is still missing, it usually was not copied: the copy (or unzip) of your game skipped it because the folder
    you copied FROM had a long path. Copy that file again, e.g. with robocopy, from a short folder.

Game version
------------
  - Only CUSA02636 with the 01.03 update is supported. Other regions or versions are refused at start.
  - Online / PlayStation Network features are not available. Trophy unlocks are recorded locally (savedata\ and
    the log); there is no on-screen trophy notification.
